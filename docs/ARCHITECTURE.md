# 架构与运行边界

React 只调用 Tauri Commands，不能直接解析日志或做关键聚合。Rust domain 实现计量规则，ingest 增量只读日志，services 统一查询/筛选/聚合，storage 负责 SQLite 事务与迁移，quota 通过官方 CLI 子进程读额度。

主链：Codex JSONL（文件所有者 + 累计快照 + 逐响应证据）→ 白名单字段 → 去重快照 + 游标事务 → 会话累计差值重算事务 → SQLite → read_dashboard → React/ECharts。

Tauri 单一采集线程正常每 3 秒枚举当前与归档目录，检查锚点，仅处理追加完整行。collector 保存 starting/synced/missing/degraded/error、上次尝试/完整成功、下次重试和本次运行恢复次数；文件或数据库失败与目录缺失采用 3/6/12/24/30 秒退避。历史解析异常单独报告，不反复重读无效行。retry_ingest 通过容量 1 的通道唤醒等待，不启动并发采集。报告与健康状态在同一锁内更新；usage-updated 在用量变化或状态转换时通知前端，ingest-health 每次尝试后更新新鲜度。下次重试时间超过 15 秒仍无新状态时 GUI 显示过期，避免旧快照冒充在线。GUI 不持续全量拉取所有历史。查询在单一只读事务中流式聚合筛选记录，使用时间/模型索引，不构造全量事件向量。全范围仍为 O(N)，百万级实测见 VALIDATION.md；更大范围需要预聚合。

额度在后台阻塞工作池启动独立 codex app-server，初始化后仅调用 account/rateLimits/read；20 秒总超时，退出清理子进程，不启用 analytics、不创建推理会话。React 每分钟请求一次且防止重叠。CLI 使用既有 Codex 登录，TokenScope 不管理账号凭据。该接口需要网络连接 Codex 官方服务。

ProviderAdapter 提供发现根目录及显式能力契约，未来 Provider 应补充自己的导入/额度服务，并复用 domain/storage。当前并没有假装所有 Provider 使用 Codex 文件格式。

前端使用 React strict、TypeScript strict、Zustand 页面状态、Tailwind/shadcn 风格 Radix Button 和 ECharts 按需模块。错误、未连接、无记录、未知增量、额度过期分别展示，不内置演示指标。

当前桌面目标 Windows 已验证；Linux/macOS 尚未构建。已生成当前用户 NSIS 安装包，不包含自动更新、托盘、开机启动、云同步或账号托管。

Schema v2 与游标算法版本 2 在升级时触发一次重读，随后恢复增量采集。计数区段恢复由 domain 的严格证据规则计算，前端只展示已持久化 epoch。被证据纠正的旧归属保留审计记录并排除统计，缺原始来源的旧记录显示未知。

时间线由 services 依据所选增量统一聚合，支持 minute/hour/day，按 UTC epoch 对齐固定区间，首末确认增量之间补零。超长范围以所选基本粒度的整数倍合并，最多 720 点；返回 interval_seconds 与 requested_grain，前端只负责本地时间标签与精确 Tooltip。合并不会抽样丢弃事件；图表点数限制不改变全部增量的聚合语义。采集恢复状态只在本次进程内保存，重启从 starting 开始，SQLite 用量与检查点持久保留。

## v0.2.0 查询、恢复与财务边界

read_dashboard 在 Tauri spawn_blocking 工作池运行。services 在同一 SQLite 读事务内先确定时间桶和最近 500 个轮次键，再流式累加 u128；事件列表最近 500 项，轮次列表最多 500 项，但每个入选轮次的全部记录均参与其聚合。会话弹窗使用 session 筛选独立查询，不依赖首页截断列表。Rust 返回 totals、timeline、estimate，同一口径复用。

受影响会话归一化按时间、确定性 usage_sort(u64) 和事件键流式处理，避免 SQLite 有符号转换截断。追加后仍重新归一化受影响会话；百万事件分布为 100 个会话的性能实测不能代表单一百万事件会话的追加延迟。

首次数据库不可打开时仍启动 GUI，并由采集线程退避重试目录创建/数据库打开。Schema 检查不在每次查询重复写迁移；未知更高版本明确拒绝打开。数据报告与健康状态在同一互斥锁中提交。

finance 使用版本化公开价格和 checked u128 nanoUSD；前端只对精确十进制金额显示舍入。后台每小时检查 24 小时汇率缓存；手动同步和后台请求有互斥保护。静态 HTTPS 地址、禁用重定向、15 秒超时、64KB 响应上限；只查询币种。关闭自动更新暂停外币换算并保留历史快照。

开发验证工具在 tools crate，桌面 crate 只声明带 desktop feature 的 GUI 二进制，避免核心单测覆盖 GUI，以及将验证程序意外打入安装包。WebView2 自动化为每个验证目录使用独立用户数据目录，避免调试端口冲突。

查询刷新采用每个筛选条件一条串行队列：正在查询时的多个采集通知只合并为一次待刷新，当前结果仍提交；切换筛选才丢弃旧筛选结果。会话详情使用同一策略，防止查询超过 3 秒采集周期时连续取消造成结果饥饿。每次执行重新计算本地今天/滚动范围。

## v0.3.0 界面与预警服务

CSS 语义变量统一双主题、按钮和图表配色；主题保存在 WebView2 本地存储，ECharts 监听主题变化更新配色。导航 Alt+数字、跳转主内容、焦点与减少动态效果保留。Alerts 组件独立调用 Tauri API，不计算阈值或额度换算。

alerts 服务在采集完成后查当前 UTC 五分钟窗口的已归一化增量，用 u128 按会话聚合；使用已有时间索引，不每次扫描全历史。额度同步后仅评估当前授权账户、新鲜且未重置的窗口。稳定规则键与事务保障幂等；alerts-updated 更新界面/未读标记，规则编辑草稿不被普通后台更新覆盖。预警是本地规则记录，没有系统弹窗或外部上传。


v0.4.0 visuals.rs 提供有界日历及 OHLC 聚合，在 services.rs 现有流式扫描中同步生成，无额外全量日志扫描。ActivityHeatmap 仅负责日历布局、键盘导航和精确值展示；Trend 通过 ECharts 模块化加载 line/bar/candlestick，按主题更新。供应商标识为本地矢量组件，未知模型保留未知来源。


v0.5.0 export.rs 复用 services::usage_query，单事务流式 CSV 与 u128 元数据汇总；export_usage 在 spawn_blocking 执行，避免阻塞 UI。文件输出仅应用 exports 目录，新建报告和 partial 完成标记，无通用前端文件系统写权限。open_exports 只打开固定本机目录。Alerts 事件刷新串行合并；过滤/页面变更后旧请求丢弃，规则草稿仅在服务端配置改变时更新。数据库返回分页锚点，避免客户端毫秒时钟排除刚创建的预警。


v0.5.1 前端导航为 Overview / Sessions / Timeline / Alerts / Settings。Quota 展示合并入 Overview，完整 Trend 只在 Timeline；共享筛选状态随导航保留。额度仍来自独立账户服务端快照，不随本地筛选变化。没有改动采集、计量、CSV 或 Schema。


v0.5.2 quota.rs 负责显式配置 / PATH / Windows 桌面安装目录程序发现及脱敏错误分类，失败不造额度。ExportUsage 使用 WebView2 原生模态 dialog 提供焦点限制、Esc 取消与关闭后焦点恢复；弹窗捕获筛选快照，确认后沿用异步 export_usage，取消不调用写入。弹窗打开时拦截应用导航快捷键。Schema 仍为 v5。


v0.5.4 usage_rate.rs 复用 Filter/usage_query，用已有时间索引读取 (now-60s, now] 的计量增量，u128 累加与整数除法后以字符串传输。独立 read_usage_rate 异步命令供 LiveRate 3 秒串行轮询；组件卸载/筛选改变丢弃旧请求，采集和速率新鲜度共同控制可用状态，不全量刷新 Dashboard。


## v0.5.6 模型生成速度估算

总览 Codex 栏改为模型可见输出生成速度（估算），替换此前的输入 + 输出消耗速率。可见输出 = output_tokens − reasoning_output_tokens；耗时 = task_complete.duration_ms − time_to_first_token_ms；tokens/s = 可见输出 × 1000 / 耗时毫秒，tokens/m = 可见输出 × 60000 / 耗时毫秒。两种单位分别从同一精确整数比率四舍五入至两位小数，避免先舍入每秒再乘 60 的误差。

仅接受 task_started / task_complete 完整、有且只有一个独立响应证据、无工具/压缩或其他非消息项、模型一致且输出计数与已归一化增量一致的轮次；拒绝缺失/非正耗时、未知计量及没有可见输出的样本。展示当前筛选匹配的最近完成轮次（最多近 15 分钟），多个并发会话取最近一条，不相加；最近轮次不合格时显示未知，不退回较早的高速度。不是实时流式测量，扣除首 Token 等待仍可能包含收尾开销，故明确标注估算。

Schema v6 新增 generation_samples 和索引，仅保存耗时、计数和响应身份哈希，不保存消息正文或工具参数。游标版本 3 首次升级只读重放一次以回填，之后继续增量采集；原计量和额度记录保留。旧版本拒绝 Schema v6，升级后应继续使用新版。read_usage_rate 保留为独立消耗统计，UI 改用 read_generation_speed。


## v0.5.9 Codex 账号资料卡

右上角改为账号入口，支持鼠标悬浮、键盘聚焦、Esc 关闭与手动刷新。使用官方 account/read（refreshToken=false）读取当前 Codex CLI 配置对应的登录方式、真实邮箱和套餐，每分钟及窗口重新激活时刷新。账号可能与使用其他 CODEX_HOME 的 Agent 实例不同；不从会话日志推断当前身份。

当前实测接口不提供账号头像、姓名或用户名，因此使用明确标注的默认头像，这些字段显示“未提供”。API Key、Bedrock、无需 OpenAI 账号、未登录、不支持、不可用及加载中分别展示。资料仅存于进程/页面内存，不写 SQLite、localStorage、报告或日志；不读取认证文件、不访问第三方头像服务，刷新失败清除旧资料。Schema v6 不变。


## v0.5.16 可见输出吞吐率与项目球体（2026-10-15）

用户确认将总览主速度指标改为近 60 秒可见输出吞吐率。旧实现每 3 秒查询，但仅接受近 15 分钟内已完成、无工具且单响应的轮次；当前真实编程工作负载多为工具/多响应轮次，因此长期显示未知。这是旧指标覆盖条件的限制，不能通过把输入消耗算作生成速度来修复。

新命令 `read_output_rate` 对当前筛选内 `(now-60s, now]` 的已确认增量计算 `output - reasoning`，跨匹配会话合计；每分钟值为窗口总量，每秒值为总量除以 60。Rust checked u128 聚合，十进制字符串跨 IPC。包含工具等待、空闲时间；按日志计量事件时间归桶，日志通常在响应结束后报告计数，不代表逐 Token 实时解码速度。没有窗口记录且采集健康时可显示 0；计量全未知、采集异常或读数过期显示未知，部分未知明确标注仅已确认部分。

界面每 3 秒查询，收到 usage-updated 或窗口重新激活时立即刷新；查询串行合并，切换筛选或卸载后丢弃旧结果。独立时钟检查读数新鲜度。旧 `read_generation_speed` 严格估算与 `read_usage_rate` 总消耗接口继续保留，主界面使用新口径。Schema v6 无迁移，不重读或改写 Codex 原始日志。

项目球体增加错峰浮动、表面呼吸和轻微光晕，使用区分更明显的八色配色及深色主题变体。用量排序变化时保留已分配的项目颜色；全部项目、精确计数和占比仍可访问。悬停/键盘聚焦暂停动效，Esc 关闭详情，减少动画模式禁用动效。半径含最小操作尺寸，面积仍不是线性消耗编码。
