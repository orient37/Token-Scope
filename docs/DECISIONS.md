# 已采用的技术决策 — v0.2.0

## 缺失历史与确认响应分别保存

匹配的独立逐响应证据只能证明本次 usage，不能给继承累计补造事件日期、模型或轮次。Schema v3 保存 carried_baseline；GUI 将其与当前已确认统计分开。未知为 0 只表示当前观察快照可解释，不宣称完整历史账单。

## 流式聚合优先于全量对象缓存

services 在 SQLite 一致读事务内流式累加 u128，并限制事件/轮次返回规模，保留全部卡片和时间线总量。当前全范围仍 O(N)，暂不引入可能失效的聚合缓存。百万事件实测约 4.5 秒；Tauri 工作池与前端串行合并保证查询期间界面可操作、连续采集不会取消所有结果。

## 参考场景价格，不替代订阅账单

当前日志不能可靠还原服务档位、长上下文和全部计费附加项。因此使用明确标注的 Standard/短上下文公开价格版本重估选中数据，并展示未覆盖模型用量。未知模型不猜价；订阅额度与 API 等价估算完全分开。金额使用 nanoUSD 整数和十进制 IPC，前端仅舍入显示。

## 公开汇率网络请求与隐私边界

采用 Frankfurter 静态 USD→HKD/CNY 查询，缓存 24 小时，保留观测日期/来源。请求只有币种，不上传用量或身份；设置可关闭。报价陈旧或失败时保留可审计的旧快照，暂停外币金额。当前不是交易汇率或财务结算系统。

## 验证工具与安装内容独立

Tauri 自动发现 src/bin 下程序会把开发基准夹带进包，因此验证工具使用独立 tools crate，桌面 crate 只声明 GUI。最终安装清单仅主程序与卸载器；验证工具、合成数据库、日志 Fixture 不分发。卸载器未经执行验证，未因测试而批量删除文件。

## 稳定性证据的边界

百万数据、故障注入和有时限的原生耐久均保存独立 TEST_ONLY 产物。每个 WebView2 测试用独立用户目录，避免并行调试器共享浏览器进程。任何短时实测不外推为数周稳定保证；签名、平台兼容和更长运行期继续单独验收。

## v0.3.0 先采用可解释阈值

没有足够基线覆盖与工作负载上下文时，不以耗量偏高断言错误。先使用用户可配置固定五分钟阈值，并明确排除未知/继承历史。额度只基于新鲜服务端百分比，保持与 Token 分离。规则记录持久化为历史观测，普通更新保持已读、严重升级重新提示；本版不发送系统通知。UI 参考 Claude Code 官方侧栏与层级分组方向，保留 TokenScope 品牌和监控流程，采用暖灰双主题与按需展开明细。
